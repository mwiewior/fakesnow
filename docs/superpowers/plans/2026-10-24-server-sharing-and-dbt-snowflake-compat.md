# Server Instance Sharing and dbt-snowflake Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A normal dbt-core project, run through dbt-snowflake, works against fakesnow twice in a row in patch mode and server mode. Server-mode logins that share a database path share one fakesnow instance.

**Architecture:** Each dbt gap is fixed in the module that already owns that kind of statement. That means the sqlglot transforms in `fakesnow/transforms/`, plus side-channel args handled in `FakeSnowflakeCursor._execute`. Server instance sharing is a registry in `fakesnow/server.py`. A new opt-in dependency group runs an end-to-end dbt test.

**Tech Stack:** Python ≥ 3.11, DuckDB 2.0, sqlglot 30.22, snowflake-connector-python, pytest, dbt-core 1.12 / dbt-snowflake 1.12 (test-only group).

**Spec:** `docs/superpowers/specs/2026-10-24-tasks-and-dbt-projects-design.md`. This plan covers **Part 0 and Part 1** only. Parts 2 (tasks) and 3 (DBT PROJECT objects) get their own plans.

## Global Constraints

- Tests assert **live Snowflake** behaviour (AGENTS.md). After each task's tests pass, run the `snowflake-check` skill on the working tree. Where live output differs from an expected value in this plan, the live value wins: update the test and the implementation, and note it in the commit message.
- One behaviour per test (AGENTS.md "Keep tests behavior-focused").
- JSON/VARIANT results compared as strings use `tests.utils.indent` / `dindent`.
- Keep behaviour with its owner (AGENTS.md):
  - session state lives on `FakeSnowflakeConnection` (`fakesnow/conn.py`);
  - statement rewrites live in `fakesnow/transforms/*`;
  - SHOW output lives in `fakesnow/transforms/show.py`;
  - temporary-object bookkeeping lives in one class (Task 2).
- dbt-core and dbt-snowflake are **not** runtime dependencies. They go in a new `dbt` dependency group.
- Status-row text for successful statements without their own message is `Statement executed successfully.` (`transforms.SUCCESS_NOP`).
- Run the suite with `uv run pytest`. Lint with `uv run ruff check . && uv run ruff format --check . && uv run pyright`.

## Review Focus

1. **A temporary object with the same name as a permanent one in the same schema.** Qualified references must resolve to the temporary object, and the permanent table must survive. Test: Task 2, `test_qualified_temporary_table_shadows_permanent`.
2. **A temporary object created in schema A, referenced as `B.name` where B has no such object.** This must stay "does not exist", not resolve to the temp object. Test: Task 2, `test_qualified_temporary_table_not_visible_from_other_schema`.
3. **Temporary objects are session-private.** A second connection on the same instance must not see them, especially in server mode where sessions share an instance. Test: Task 2, `test_qualified_temporary_table_is_session_isolated`.
4. **Two logins with the same `FAKESNOW_DB_PATH` written as different strings** (relative vs absolute, trailing slash) must share one instance and not hit the DuckDB file-lock error. Test: Task 1, `test_db_path_sessions_share_instance_across_path_spellings`.
5. **`QUERY_TAG` set with quotes or `$$` strings, then unset.** `SHOW PARAMETERS` must report the value and then `''`. Test: Task 4, `test_query_tag_unset_restores_default`.

def test_db_path_sessions_share_instance(server: dict, tmp_path: Path) -> None:
    params = server["session_parameters"] | {"FAKESNOW_DB_PATH": str(tmp_path)}
    with (
        snowflake.connector.connect(**(server | {"session_parameters": params}), database="db1", schema="s1") as c1,
        snowflake.connector.connect(**(server | {"session_parameters": params}), database="db1", schema="s1") as c2,
    ):
        c1.cursor().execute("create table t (id int)")
        c1.cursor().execute("insert into t values (1)")
        assert c2.cursor().execute("select id from t").fetchall() == [(1,)]


def test_db_path_sessions_share_instance_across_path_spellings(server: dict, tmp_path: Path) -> None:
    # same directory, spelled with a trailing slash and a "." segment
    p1 = server["session_parameters"] | {"FAKESNOW_DB_PATH": str(tmp_path)}
    p2 = server["session_parameters"] | {"FAKESNOW_DB_PATH": f"{tmp_path}/./"}
    with (
        snowflake.connector.connect(**(server | {"session_parameters": p1}), database="db1", schema="s1") as c1,
        snowflake.connector.connect(**(server | {"session_parameters": p2}), database="db1", schema="s1") as c2,

def test_server_default_db_path_persists(tmp_path: Path) -> None:

        fakesnow.server(db_path=str(tmp_path)) as kwargs,

**Interfaces:**
- Produces:
  - `TemporaryObjects(duck_conn: DuckDBPyConnection)`
  - `TemporaryObjects.record(expression: Expr, catalog: str | None, schema: str | None) -> None`: call after executing a `CREATE TEMPORARY TABLE|VIEW`; it registers the object's OID with the (catalog, schema) it was created in.
  - `TemporaryObjects.owner(name: str) -> tuple[str | None, str | None] | None`: the (catalog, schema) of the live temporary table or view called `name` in this session, or None.
  - `transforms.temporary_objects(expression: Expr, temporaries: TemporaryObjects, current_database: str | None, current_schema: str | None) -> Expr`
- `TableStages.record_temporary_table` and `lookup_sql` keep their behaviour. All existing stage and COPY tests must still pass unchanged.

Behaviour of `temporary_objects`:
- `CREATE [OR REPLACE] TEMPORARY TABLE|VIEW cat.sch.name` loses its catalog and schema, so DuckDB creates it in `temp.main`. The original qualifiers stay available to `record` through the args the cursor passes; record with `table.catalog or current_database`, `table.db or current_schema`.
- Any `exp.Table` reference whose name is a live temporary object, and whose qualifiers (defaulting missing parts to the current database and schema) equal that object's owner, is rewritten to `temp.main.<name>`. This covers SELECT, INSERT, DELETE, MERGE, DROP and DESCRIBE.
- A reference to the same name from another schema is left alone, so it resolves to a permanent table or fails with "does not exist".
- Place it in `_transform` right after `upper_case_unquoted_identifiers` and before `set_schema`, so every later transform sees the rewritten table.

## Live checks

Verified with `snowflake-check` on 2026-10-25 (Snowflake 10.38), and fakesnow corrected to match:

- SHOW GRANTS ON returns a ninth column, `granted_by_role_type` (`'ROLE'`). A name part that isn't an upper case
  identifier is quoted, eg: `DB1."Mixed".T1`. A missing object's sqlstate is `42S02`. Snowflake's `created_on` is
  TIMESTAMP_LTZ, which fakesnow can't describe (it reports TIMESTAMP_TZ, as for other LTZ columns).
- GRANT on one object and FUTURE grants return `Statement executed successfully.`; GRANT ... ON ALL returns
  `Statement executed successfully. <n> objects affected.` with the objects it covers, and REVOKE the grants it removed,
  which fakesnow reports as 0 as it doesn't record grants.
- `SYSTEM$CANCEL_ALL_QUERIES(<own session id>)` returns `0 cancelled.`, another session's id `invalid session id`.
- `ALTER TABLE a SWAP WITH a` succeeds and changes nothing. Swapping a temporary table with a permanent one fails with
  `001486 (42601): Swapping of a temporary table with another non-temporary table is not allowed.`, with a view with
  `002203 (02000): SQL compilation error: Object found is of type 'VIEW', not specified type 'TABLE'.`
- COMMENT ON returns `Statement executed successfully.`
- The temporary-table status rows and the QUERY_TAG parameter row are as fakesnow returns them.

Not modelled: warehouses and roles that don't exist. Snowflake rejects `USE WAREHOUSE` of a missing warehouse
(002043), leaves the current warehouse NULL when connecting with one, and rejects grants to a missing role; fakesnow
treats every warehouse and role as existing, so the tests use names that exist in a new account, eg: `COMPUTE_WH`,
`PUBLIC`. Snowflake also lists temporary tables in `information_schema.tables`, and returns
`<name> already exists, statement succeeded.` for CREATE TABLE IF NOT EXISTS of an existing table; fakesnow doesn't.
